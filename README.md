# رهیار — Life Execution OS

پیاده‌سازی کامل و قابل‌اجرای پروپوزال «رهیار» به‌صورت یک PWA فارسی، راست‌به‌چپ و آفلاین‌پذیر.

رهیار یک لیست کار با هوش مصنوعی نیست؛ یک سیستم اجرای زندگی است: در هر لحظه یک پیشنهاد روشن برای «الان» می‌دهد، دلیلش را می‌گوید، حوزه‌های زندگی را در برابر هم می‌گذارد و بعد از هر قدم بازخورد گرم و انسانی می‌دهد.

---

## استقرار روی GitHub Pages

این نسخه مخصوص GitHub Pages آماده شده است. تفاوت‌های کلیدی با نسخهٔ قبلی:

- **base خودکار**: مسیر پایهٔ دارایی‌ها از `GITHUB_REPOSITORY` (یا `BASE_PATH`) خوانده می‌شود؛ لازم نیست دستی چیزی را برای نام مخزن تغییر دهی.
- **منیفست نسبی**: `manifest.webmanifest` با مسیرهای نسبی کار می‌کند، پس PWA هم روی ریشهٔ دامنه و هم در زیرمسیر `/<repo>/` نصب می‌شود.
- **سرویس‌ورکر آگاه‌به‌base**: کش آفلاین و fallback صفحهٔ اصلی با پیشوند مسیر انتشار ساخته می‌شود، نه با `/` مطلق.
- **workflow آماده**: `.github/workflows/deploy-pages.yml` در هر push روی `main` می‌سازد و منتشر می‌کند.

### ۱. ساخته و push کن

```bash
git init -b main
git add .
git commit -m "Rahyar: GitHub Pages ready"
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
```

> `dist/` و `node_modules/` در `.gitignore` هستند و نباید commit شوند؛ ساخت در GitHub Actions انجام می‌شود.

### ۲. Pages را فعال کن

در مخزن: **Settings → Pages → Build and deployment → Source: GitHub Actions**

اگر Pages هنوز فعال نشده باشد، اولین اجرای workflow با پیام روشن متوقف می‌شود؛ همین یک تنظیم را یک بار انجام بده.

### ۳. تمام

هر push روی `main` به‌طور خودکار build و deploy می‌شود. آدرس سایت:

```
https://USERNAME.github.io/REPO/
```

- اگر نام مخزن `USERNAME.github.io` باشد، سایت روی ریشهٔ دامنه منتشر می‌شود و base خودکار `/` می‌شود.
- اگر دامنهٔ اختصاصی وصل کنی (Settings → Pages → Custom domain)، `actions/configure-pages` مقدار خالی برمی‌گرداند و base خودکار `/` می‌شود.

### ساخت دستی با base مشخص

اگر می‌خواهی خودت build کنی و مثلاً `dist/` را روی شاخهٔ `gh-pages` بگذاری:

```powershell
$env:BASE_PATH="/REPO/"; npm run build   # PowerShell
```

```bash
BASE_PATH=/REPO/ npm run build           # bash
```

ترتیب اولویت base: `BASE_PATH` ← `GITHUB_REPOSITORY` ← `/`. مقدار خالیِ `BASE_PATH` به معنی «ریشهٔ دامنه» است (همان چیزی که برای دامنهٔ اختصاصی لازم است).

## اجرا (محلی)

```bash
npm install
npm run dev        # http://127.0.0.1:5173
```

نسخهٔ تولید:

```bash
npm run build
npm run preview    # http://127.0.0.1:4173
```

نسخهٔ ساخته‌شده در `dist/` قرار می‌گیرد و باید از طریق یک وب‌سرور (مثل `preview` یا GitHub Pages) باز شود؛ باز کردن مستقیم `dist/index.html` با `file://` کار نمی‌کند.

### نصب به‌عنوان اپ (PWA)

- در Chrome/Edge دسکتاپ: آیکن نصب در نوار آدرس یا «تنظیمات ← نصب روی دستگاه».
- در Android: منوی مرورگر ← «افزودن به صفحهٔ اصلی» / «نصب برنامه».
- در iOS Safari: Share ← Add to Home Screen.

سرویس‌ورکر در نسخهٔ production ثبت می‌شود و بعد از یک بار باز شدن، اپ آفلاین هم بالا می‌آید. برای آزمون دستی: یک بار آنلاین باز کن، بعد Network را قطع کن و صفحه را رفرش کن.

## معماری

```
src/
  App.tsx                 پوستهٔ اپ، ناوبری RTL، تب‌ها، شیت‌های سراسری
  screens/
    Onboarding.tsx        شروع آرام، حوزه‌ها، برنامهٔ نمونه
    Now.tsx               پیشنهاد الان، صف بعدی، نبض امروز، بازیابی، تمرکز عمیق
    Advisor.tsx           شش دستور، پاسخ زنده، گفت‌وگو
    Portfolio.tsx         پرتفوی، دونات توجه، بینش‌ها، ویرایش حوزه
    Plan.tsx              کارها، اهداف، آیین‌ها، دفتر تصمیم
    Review.tsx            مرور پایان روز و تاریخچه
  lib/
    engine.ts             امتیازدهی، پرتفوی توجه، بینش‌ها، شمارش قدم‌ها
    date.ts               تاریخ محلی، جلالی، موعد، آیین بعدی، اعداد فارسی
    content.ts            لحن مشاور، پیام‌های پاداش، بریف واگذاری
    storage.ts            ذخیره/بازیابی، اعتبارسنجی و ترمیم داده، پشتیبان
    seed.ts               برنامهٔ نمونهٔ کامل
  store/store.tsx         ردیوسر مرکزی، آیین‌ها، مرور، undo، پایداری
  components/             آیکن‌ها، شیت، فیلد تاریخ، اجزای پایه
  ui/                     Toast، کارت پاداش، دستورهای UI
```

- **همهٔ داده‌ها محلی‌اند**: `localStorage` با کلید `rahyar.state.v1`؛ هیچ درخواست شبکه‌ای برای داده وجود ندارد.
- **پردازش «هوشمند» بدون وابستگی به API**: موتور امتیازدهی شفاف و قابل‌تست است؛ لحن مشاور با قالب‌های فارسی و زمینهٔ واقعی ساخته می‌شود.
- **آفلاین**: سرویس‌ورکر در build تولید می‌شود و دارایی‌های هش‌شده را پیش‌کش می‌کند.
- **دسترس‌پذیری**: ناوبری با کیبورد، بستن شیت با Escape، تلهٔ فوکوس، aria-label، احترام به `prefers-reduced-motion`.

## تست

```bash
npm test        # ۴۰ تست واحد: موتور، تاریخ، محتوا، ردیوسر، storage
npm run test:e2e
```

`test:e2e` یک تست واقعی با Chrome است و به مسیر Chrome نیاز دارد:

```bash
CHROME_PATH="C:\Program Files\Google\Chrome\Application\chrome.exe" npm run test:e2e
```

این تست‌ها شامل: onboarding، تکمیل و undo، ورود سریع، شیت کار، واگذاری، شش دستور مشاور، ساخت/ویرایش حوزه، ویرایش کار، هدف و نقطهٔ عطف، آیین، دفتر تصمیم، بایگانی/بازگردانی، مرور روز، پشتیبان‌گیری و بازیابی، ماندگاری پس از reload، آفلاین بودن PWA، حالت بازیابی و ریسپانسیو در ۳۲۰px است.

اسکرین‌شات‌ها در `artifacts/` ذخیره می‌شوند (این پوشه بخشی از خروجی تولید نیست).

## ساخت بستهٔ اندروید (اختیاری)

PWA همین حالا روی اندروید نصب می‌شود. اگر APK مستقل می‌خواهی، با Capacitor:

```bash
npm install @capacitor/core @capacitor/cli @capacitor/android
npx cap init "رهیار" com.rahyar.app --web-dir=dist
npm run build
npx cap add android
npx cap copy android
npx cap open android
```

سپس در Android Studio، APK/AAB را بساز. برای استفاده از ورودی صوتی، WebView باید از Web Speech API پشتیبانی کند؛ در غیر این صورت دکمهٔ میکروفون با پیام محترمانه به تایپ برمی‌گردد.

## داده و حریم خصوصی

- نام، حوزه‌ها، کارها، اهداف، آیین‌ها، تصمیم‌ها و مرورها فقط روی دستگاه ذخیره می‌شوند.
- «تنظیمات ← نسخهٔ پشتیبان» یک JSON کامل می‌دهد و همان فایل با دکمهٔ بازگردانی قابل import است.
- «پاک کردن داده‌های نمونه» فقط داده‌های `source: seed` را حذف می‌کند و داده‌های خودت را نگه می‌دارد.
- در صورت خراب شدن داده، نسخهٔ خراب در `rahyar.state.v1.corrupt.*` نگه داشته می‌شود و اپ با حالت تازه بالا می‌آید.
